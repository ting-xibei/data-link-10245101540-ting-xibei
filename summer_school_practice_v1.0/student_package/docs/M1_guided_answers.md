
## 1. `raw_states.json` 中的一条数组与“每个目标只保留最新记录”的当前态势表有什么区别？

`raw_states.json` 中的一条数组是外部数据源的一条原始状态记录。字段按固定索引排列，含义需要通过 `opensky_field_dictionary.csv` 解释；记录中还可能存在空值、无效值、延迟或重复。

当前态势表是处理后的结果：先将数组解析为结构化字段并完成必要校验，再按 `target_id` 分组、按时间排序，并为每个目标选择最新的可接受记录。因此，原始数组只是输入记录，不能直接等同于当前态势。

## 2. 为什么发送方内部结构不能直接等同于在线传输字节串？

发送方内部结构保存的是带字段名称和业务语义的数据，例如时间、经纬度、速度、空值、字段来源和有效性；其内存表示由程序语言决定，不适合直接作为通信格式。

在线传输的 TeachingLink 消息必须遵守双方共同约定的固定格式：每帧 41 字节，使用大端字节序、固定字段偏移、无符号整数定点编码、状态位、有效位和校验和。发送方必须先将内部字段序列化为该字节格式，接收方才能稳定校验并恢复出接收方内部记录。

## 3. `message_valid`、字段有效性和业务数据质量分别回答什么问题？

- `message_valid` 回答“整帧消息是否通过 TeachingLink 接收校验”。检查内容包括长度、帧头、版本、类型、校验和、保留位、标志与占位值的一致性，以及必需字段。可选字段缺失不自动导致整帧无效。
- 字段有效性回答“某个可选字段能否被解释和使用”。TeachingLink 使用 `validity_flags` 分别标记经纬度、高度、速度、航向、垂直速度和呼号。有效位为 1 且编码值为 0 表示真实零值；有效位为 0 且占位字节为 0 表示字段缺失。
- 业务数据质量回答“已经解码的数据是否适合后续态势使用”。本实验检查位置是否完整、数据是否延迟、记录是否重复、航向是否越界等问题。

三者不能互相替代：一帧可以 `message_valid=true`，但仍然缺少纬度并产生位置缺失告警；通过帧校验也不证明数据来源真实或飞行状态安全。

## 4. 为什么字节序、位宽、比例因子、偏置和保留位必须由通信双方共同约定？

这些参数共同决定同一段字节的唯一解释方式：

- 字节序决定多字节整数的高低位排列；
- 位宽决定字段边界、数值范围和后续字段偏移；
- 比例因子决定整数编码的物理分辨率；
- 偏置用于将含负值的物理范围映射为无符号整数；
- 保留位固定为 0，用于发现异常，并为后续协议扩展保留空间。

只要双方任一项约定不一致，接收方就可能得到错误的字段边界或物理量，即使该字节串表面上仍可被读取。因此这些规则必须写入协议，并由发送端和接收端按同一规范实现。

## 5. CSV 与 SQLite 在本实践中分别承担什么角色？为什么 SQLite 不是必做前置条件？

CSV 是文本表格文件，主要承担阶段间的数据交换和结果展示。它不需要数据库环境，能够直接查看，也容易被 Python、Excel 等工具读取。它适合字段结构固定、数据量较小、以整批写入和整批读取为主的教学数据。

SQLite 是嵌入式关系数据库，主要承担长期、结构化的持久化。与 CSV 相比，它支持字段类型和约束、索引、事务以及 SQL 条件查询，能够高效完成按目标、时间范围或其他条件检索，也更适合持续追加、局部更新和管理多批数据。CSV 缺少这些数据库能力：复杂查询通常需要先读取整个文件，更新记录往往需要重写文件，并发写入和一致性也需要程序自行处理。

本实验的数据量小、批次固定，程序主要按阶段整批生成和读取文件，不需要并发访问、频繁更新或复杂查询。因此使用 CSV 已足以保存接收记录，并支持后续航迹、当前态势、语义映射和质量检查，SQLite 不是完成必做链路的前置条件。

课程仍提供 SQLite 扩展，是为了展示数据量和历史批次增加后的工程化存储方式：利用索引提高按目标和时间查询的效率，利用约束和事务保证数据一致性，并避免每次查询都扫描完整 CSV。它在当前小样例中不是必需，但在长期积累、多条件查询和持续更新的场景中更合适。

## 6. 主要工程风险、影响和处理方式是什么？

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 字段缺失 | 位置或运动状态不完整；若把缺失误写成 0，会改变原始语义 | 必需字段不可用时拒绝正常封装；可选字段保持空值，并通过有效位表示。时间优先使用 `time_position`，否则回退到 `last_contact`；高度优先使用气压高度，否则回退到几何高度并记录来源。真实 0 值必须保留。 |
| 接口延迟 | 旧记录可能被误当成当前状态 | 保留记录时间和批次时间并计算时间差；本实验中差值严格大于 60 秒时产生延迟告警。 |
| 消息损坏 | 接收方可能恢复出错误字段，或者无法确定帧边界 | 接收端依次检查长度、帧头、版本、类型、校验和、保留位及必需字段；非法帧写入验证日志，不进入正常处理链，也不能导致程序整体崩溃。 |
| 量化误差或越界 | 解码值与原值存在误差；越界值可能产生错误编码 | 使用规定的 `Q(y) = floor(y + 0.5)`、比例因子和偏置；编码前检查物理量范围，禁止用截断、掩码或取模静默处理越界值；有效字段往返误差原则上不超过一个量化单位。 |
| 存储失败 | 接收记录或阶段成果丢失，后续处理缺少可靠输入 | 显式捕获并记录文件或数据库写入错误，不把失败写入当作成功；保留已经生成的上游成果。SQLite 为选做路径，其失败不应取消必做 CSV 成果。 |

## 系统边界

TeachingLink 是学校自定义的教学协议，仅用于固定帧编解码练习，不对应 ASTERIX、ADS-B/Mode-S、Link 16、企业装备协议或任何行业标准。本实验不进行真实 ADS-B/Mode-S 信号解码、实时网络访问、重传、拥塞控制或飞行安全判定。
